# Установка и запуск на Wiren Board 8 (wb-rules)

Скрипты выполняются движком правил **wb-rules**, который уже входит в прошивку
Wiren Board. Установка сводится к копированию двух `.js`-файлов в репозиторий
правил `/etc/wb-rules/`. Отдельный Node.js, npm и systemd-сервисы **не нужны** —
wb-rules сам следит за каталогом и мгновенно перезагружает изменённые правила.

---

## Шаг 1. Подготовка: проверка опроса модулей RS-485

Прежде чем ставить правила, убедитесь, что `wb-mqtt-serial` уже опрашивает
WB-WRM2 и WB-MAI6 и публикует нужные топики.

1. Подключитесь по SSH (логин `root`, пароль — серийный номер контроллера,
   если не меняли):

   ```sh
   ssh root@<IP-адрес-контроллера>
   ```

2. Проверьте конфигурацию serial-устройств (обычно `/etc/wb-mqtt-serial.conf`
   или фрагменты в `/etc/wb-mqtt-serial.conf.d/`). В ней должны быть описаны:
   - `wb-wrm2` с адресом **134**;
   - `wb-mai6` с адресом **28**, включённые каналы `IN 1 N Temperature`,
     `IN 2 P Temperature`, `IN 1 P Temperature`, `Internal Temperature`.

   Проще всего добавить модули через веб-интерфейс WB: *Настройки →
   Точки доступа / Конфигуратор устройств (wb-mqtt-serial)*.

3. Убедитесь, что топики появляются в брокере:

   ```sh
   mosquitto_sub -v -t 'wb-mai6_28/#' -t 'wb-mrwm2_134/#'
   ```

   Вы должны видеть сообщения вида
   `wb-mai6_28/IN 1 N Temperature 23.5` и `wb-mrwm2_134/K1 0`.
   Обратите внимание: в именах каналов есть **пробелы** — в скриптах они
   уже учтены. Пока топики не появились, правила ставить можно, но управлять
   будет нечем.

4. Проверьте, что сервис правил работает:

   ```sh
   systemctl status wb-rules
   ```

## Шаг 2. Копирование скриптов в репозиторий правил

### Вариант А — с рабочего компьютера (рекомендуется)

```sh
scp climate_ui.js climate_ctrl.js root@<IP-адрес-контроллера>:/etc/wb-rules/
```

### Вариант Б — прямо в веб-интерфейсе WB

Веб-интерфейс Wiren Board встроен: *Сервис → Настройка правил* (или ссылка
«Rules» в меню). Создайте там два файла `climate_ui.js` и `climate_ctrl.js`,
вставьте в каждый содержимое соответствующего скрипта и сохраните
(Ctrl+S) — wb-rules перезагрузит правила автоматически.

### Вариант В — вручную на контроллере

```sh
nano /etc/wb-rules/climate_ui.js      # вставить содержимое, Ctrl+O, Ctrl+X
nano /etc/wb-rules/climate_ctrl.js
```

После копирования файлы должны выглядеть так:

```
/etc/wb-rules/
├── climate_ui.js
└── climate_ctrl.js
```

Права на исполнение файлам правил не требуются (достаточно `644`).

## Шаг 3. Проверка загрузки правил

1. Посмотрите лог wb-rules — в нём должны появиться строки:

   ```sh
   journalctl -u wb-rules -f
   ```

   Ожидаемое:
   ```
   climate_ui: правила загружены
   climate_ctrl: правила загружены
   climate_ctrl: инициализация, безопасная позиция OFF. MIN_ON=180s MIN_OFF=180s STALE=60s
   ```

2. Убедитесь, что виртуальное устройство создалось:

   ```sh
   mosquitto_sub -v -t 'devices/climate_ui/#' &
   ```

   Должны появиться retained-сообщения `.../Meta`, `.../Name`, каналы
   `Mode`, `Manual`, `TargetTemp`, `Hysteresis`, `CompressorCommand` и т.д.
   (топики каналов содержат `/` вместо пробелов, например
   `devices/climate_ui/controls/TargetTemp`).

3. В веб-интерфейсе WB (*Главная / «Devices»*) появится устройство
   **Climate Chamber UI** с переключателями и полями уставки.

## Шаг 4. Пусконаладочный тест (без компрессора!)

> ⚠️ На время теста **отключите компрессор от реле WB-WRM2** (или переведите
> питание модуля в режим отладки), чтобы не гонять реальный компрессор
> короткими циклами.

1. Задайте уставку и включите автоматический режим из UI (или командами):

   ```sh
   mosquitto_pub -r -t 'devices/climate_ui/controls/TargetTemp/set' -x 5
   mosquitto_pub -r -t 'devices/climate_ui/controls/Hysteresis/set' -x 0.5
   mosquitto_pub -r -t 'devices/climate_ui/controls/Mode/set' -x 1
   mosquitto_pub -r -t 'devices/climate_ui/controls/Manual/set' -x 0
   ```

2. Проследите, что параметры дошли до термостата:

   ```sh
   mosquitto_sub -v -t 'wb/climate/set/#'
   ```

   Должны быть: `wb/climate/set/Mode 1`, `.../TargetTemp 5` и пр.

3. Смоделируйте «жару» в камере, опубликовав фейковые температуры
   (wb-rules воспримет их как новые значения каналов):

   ```sh
   mosquitto_pub -r -t 'wb-mai6_28/IN 1 N Temperature' -x 12
   mosquitto_pub -r -t 'wb-mai6_28/IN 2 P Temperature' -x 12
   ```

   Через несколько секунд при `T = 12 > 5 + 0.5` термостат должен выдать
   команду 1 (если прошёл минимальный простой 180 с после старта):

   ```sh
   mosquitto_sub -v -t 'wb/climate/fb/#' -t 'wb-mrwm2_134/K1'
   # ожидаем: wb/climate/fb/CompressorCommand 1  и  wb-mrwm2_134/K1 1
   ```

4. Смоделируйте «холод» (`-x 2` для обоих датчиков) — после истечения
   MIN_ON_SEC команда должна стать 0.

5. Проверьте ручной режим: `Manual=1` → команда 1; `Mode=0` → команда 0.

6. Верните компрессор на место.

## Шаг 5. Эксплуатация

- Все органы управления доступны в веб-интерфейсе WB на странице устройства
  **Climate Chamber UI**:
  - `Mode` — OFF/AUTO;
  - `Manual` — ручной принудительный пуск (только в AUTO);
  - `TargetTemp`, `Hysteresis` — уставка и гистерезис;
  - `CompressorCommand` — readonly-выход термостата;
  - `CompressorActual` — фактическое состояние реле K1;
  - четыре канала температур.
- Настройки защиты компрессора меняются в начале `climate_ctrl.js`
  (`MIN_ON_SEC`, `MIN_OFF_SEC`, `STALE_SEC`) либо переменными окружения
  сервиса wb-rules (`CLIMATE_MIN_ON_SEC` и т.п., через drop-in
  `systemctl edit wb-rules`).

### Обновление скриптов

Просто перезапишите файлы — wb-rules применит изменения на лету:

```sh
scp climate_ui.js climate_ctrl.js root@<IP>:/etc/wb-rules/
journalctl -u wb-rules -n 20    # убедиться, что ошибок нет
```

Либо правьте прямо в веб-редакторе правил и сохраняйте.

## Типичные проблемы

| Симптом | Причина / решение |
|---|---|
| Устройство `climate_ui` не появилось в UI | Ошибка синтаксиса в файле правил — смотрите `journalctl -u wb-rules`; проверьте, что файл лежит именно в `/etc/wb-rules/` и имеет расширение `.js` |
| Температуры в UI показывают `null` | Нет сообщений в топиках `wb-mai6_28/...` — см. Шаг 1 (конфиг wb-mqtt-serial, физика RS-485, терминация, A/B не перепутаны) |
| Команда `1` не появляется | Не прошёл таймер MIN_OFF/MIN_ON (ждём ≤3 мин) или `Mode=OFF` / данные старше 60 с (STALE) — смотрите лог `climate_ctrl:` |
| Реле не переключается при команде | Публикуйте/проверяйте точно топик `wb-mrwm2_134/K1`; проверьте, что WB-WRM2 описан в wb-mqtt-serial с адресом 134 и типом `wb-wrm2` |
| После ребута камеры команда самопроизвольно снимается | Это штатное поведение: безопасная позиция OFF при старте правил; включите `Mode=AUTO` заново |
